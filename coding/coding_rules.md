# Coding Rules

## Final Outcome Coding

The five archived category definitions are retained below. They specify the meaning of the labels; they do not establish that each stored code was correctly selected from its source narrative.

| Final outcome | Coding condition |
| --- | --- |
| Diplomatic resolution | Negotiated settlement, withdrawal, mutually accepted compromise, or stabilized agreement |
| Protracted stalemate | No general war and no settlement, with sustained coercive standoff |
| Full-scale war | Large-scale kinetic escalation between principal actors |
| Limited conflict | Localized military clash without transition to general war |
| Internal collapse | Domestic breakdown, regime crisis, or leadership fragmentation dominates final pathway |

## Selection and Verification Status

The run-level table stores one five-category outcome and its three-category aggregation per execution. Some source PDFs contain multiple final branches. The rule used to select one code per execution from those branches has not been recovered, so the source branch, PDF page, and selection rationale remain unresolved.

`record_linkage_status=indexed` records a file association. An indexed path is not evidence that the PDF narrative supports the stored outcome or state values. As of 6 September 2026, all 120 rows in `final_outcome_coding_run_level.csv` have `semantic_verification_status=unresolved`. The existing codes and numerical values have been preserved; no recoding has been performed.

Semantic verification requires a trace from each coding row to the actual source execution, selected branch or turn, PDF page and supporting text, and the reason for assigning the code. Until that trace is established, the analysis reproduces the archived coding table conditionally. See the [provenance audit](../docs/provenance_audit.md) for the documented discrepancies and evidence limits.
